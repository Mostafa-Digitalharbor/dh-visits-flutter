# نواقص الباك إند المكتشفة في اختبار E2E (2026-07-14)

اختبرت التطبيق end-to-end بنفسي (نسخة release على الإيموليتر). التطبيق نفسه سليم،
لكن لقيت **مشكلتين في الباك إند** بيوقفوا سيناريوهات أساسية. لكل واحدة: الشرح +
الحل + إزاي تختبرها.

---

## المشكلة 1 (حرجة): الموظف مش بيشوف الزيارة اللي المدير عملها له

### الشرح
لما **المدير** يعمل زيارة ويحدّد موظف مسؤول (مثلاً Mona تعمل زيارة لـ Sam)،
**الموظف Sam مش بيلاقي الزيارة في قائمته خالص** — فمش قادر يفتحها ولا يبدأها.

### السبب الجذري (مؤكّد بالـ API)
`GET/POST /api/visit/my` بيفلتر بـ **مين أنشأ الزيارة** (`create_uid`)، مش بـ
**الموظف المسؤول** (`employee_id`). مثال حيّ (الزيارة VIS/2026/00055):

```
create_uid  = Mona Manager (7)
employee_id = Sam Sales (6)
state       = approved

/api/visit/my  كـ Sam        → 42 زيارة، مفيهاش 55  ❌
call_kw domain [employee_id.user_id = Sam] → 43 زيارة، فيها 55  ✅
```

### الحل المطلوب
غيّروا دومين `/api/visit/my` يفلتر بالموظف المسؤول بدل (أو بالإضافة لـ) المُنشئ:

```python
# بدل: domain = [('create_uid', '=', request.env.user.id)]
domain = [('employee_id.user_id', '=', request.env.user.id)]
# أو لو عايزين الاتنين (اللي أنشأها + اللي مسؤول عنها):
# domain = ['|', ('employee_id.user_id','=',uid), ('create_uid','=',uid)]
```

> المنطقي إن "زياراتي" = الزيارات اللي **أنا مسؤول عن تنفيذها**، بغضّ النظر مين
> أنشأها. ده أهم إصلاح — من غيره ميزة "المدير يخطّط لموظفيه" مكسورة تمامًا.

### إزاي تختبرها
1. سجّل كمدير، اعمل زيارة وحدّد موظف تابع لك كمسؤول.
2. سجّل بحساب الموظف ده → لازم الزيارة تظهر في قائمته ويقدر يفتحها/يبدأها.

## المشكلة 2: إرسال الإشعارات (FCM) لسه مش شغّال على الداتا بيز

### الشرح
رغم إنكم قلتوا إن ملف `PUSH_MISSING_FCM_SEND.md` خلص، **الإشعار لسه مش بيوصل**.
التطبيق بيسجّل التوكن صح (register_device بيرجّع 200، والتوكن متخزّن active)، لكن
لمّا موظف يعمل submit، **صفر إشعار بيوصل** لموبايل المدير.

### السبب الجذري (مؤكّد بفحص الداتا بيز)
```
ir.config_parameter (fcm/firebase/service_account) → فاضي
service-account JSON attachment                    → فاضي
ir.logging (fcm/firebase/push)                      → فاضي
```
يعني **ملف الـ Service Account لسه مش متحطّط على الداتا بيز** (مفيش system parameter
`dh_visit.fcm_service_account` ولا أي مفتاح مشابه) → دالة الإرسال بتخرج بدري من
غير ما تبعت. الكود ممكن يكون اتكتب، بس **الاعتماد (credential) مش متكوّن**.

### الحل المطلوب
1. حطّوا فعليًا محتوى **Service Account JSON** (من مشروع Firebase **`visits-app1`**،
   sender `1029698829865`) في system parameter `dh_visit.fcm_service_account`
   (أو المكان اللي الكود بيقرأ منه — راجعوا `PUSH_MISSING_FCM_SEND.md`).
2. اتأكدوا إن `_notify(...)` بتتنادى فعلًا عند submit/approve/... إلخ.

### إزاي تختبرها
1. بعد ضبط الـ Service Account، خلّي موظف يعمل submit لزيارة.
2. **شوفوا لوج السيرفر** لحظتها — لازم يبان طلب `messages:send` ورد **200** من FCM.
3. لو الرد 403/404 (SenderId/project error) → الـ Service Account من مشروع غلط
   (مش `visits-app1`).
4. أسرع تأكيد: ابعتوا Test message من Firebase Console → Cloud Messaging لتوكن
   الجهاز، لازم يوصل فورًا.
